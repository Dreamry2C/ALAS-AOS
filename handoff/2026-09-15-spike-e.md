## 关键事实（跨对话必须记住）

- **`screencap -d` 与 `input -d` 是两个命名空间**：前者吃 `dumpsys SurfaceFlinger --display-id` 的 int64 physical id；后者吃 logical display id（给 physical id 会 `IllegalArgumentException`）。**m0 §41 的血案就是因为用了 logical id 调 screencap。**
- **VD 变黑 ≠ 崩溃**：是 display group 电源请求 OFF → DPC 的 ColorFade 层盖屏（`dumpsys SurfaceFlinger` 里该屏只剩 `1 Layers / Output Layer (ColorFade#…)`）。shell 域无解：`cmd display power-reset` 无效、`requestDisplayPower(id,ON)` 只恢复窗口 surface、`am start` 不点亮。规避=在真屏亮/设备 Awake 时建屏，或熄灭后重建。
- **scrcpy-server 三件套**：`cleanup=false`（否则辅助进程 `unlinkSelf()` 删 jar）、必须有客户端保持连接（否则 server 退出）、PC 侧后台任务超时要设长（否则 `adb shell` 被杀 = VD 死）。
- **HONOR 显示栈私货**：`DisplayManagerGlobal.requestDisplayPower(int,boolean)` 与 `SurfaceControl.getPhysicalDisplayIds()` 在本 ROM 都不存在（scrcpy 相应分支静默降级）。
- 设备 `mWakefulness` 决定"建屏即亮"还是"建屏即黑"；本次 VD 创建后 1~2 分钟内还会被 framework 自己翻成 OFF（触发条件未定，待复跑量化）。
